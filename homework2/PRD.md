## 1. 产品概述

“一箭又一箭”是一款点击式网格解谜小游戏。棋盘上放置朝向上、下、左、右的单格箭头。玩家需要观察箭头的方向和相互遮挡关系，按照合理顺序点击箭头，使全部箭头依次飞出棋盘。

游戏的核心体验是：

1. 判断某支箭头沿自身方向是否有阻挡；
2. 点击无阻挡箭头，使其飞出并消失；
3. 点击被阻挡箭头时获得明确的碰撞反馈并消耗一次失误机会；
4. 清空当前关卡后进入下一关，失误机会耗尽则失败并允许重试。

本项目只实现基础的“单格箭头”玩法，不要求复杂机关、长箭头或其他扩展玩法。

## 2. 产品目标与范围

- 无阻挡时播放飞出效果并移除箭头。

## 4. 核心游戏规则

### 4.1 棋盘与箭头

- 棋盘由规则的行列网格组成。
- 每个箭头只占一个网格。
- 箭头方向只有四种：上（↑）、下（↓）、左（←）、右（→）。
- 空网格不放置箭头。

### 4.2 路径检测

点击箭头后，从箭头相邻的下一格开始，沿箭头方向逐格检查，直到棋盘边界：

- 只检查箭头前进方向上的同一行或同一列。
- 斜线方向的箭头不构成阻挡。
- 箭头后方的箭头不构成阻挡。
- 检查过程中遇到任意其他箭头，即判定为有阻挡。
- 走到边界仍未遇到箭头，即判定为无阻挡。

示例：

```text
→ · · ↑ ·   # 右箭头右侧仍有箭头，不能飞出
↑ · · · →   # 最右侧右箭头右侧无箭头，可以飞出
```

### 4.3 点击结果

| 条件 | 状态变化 | 视觉反馈 |
| --- | --- | --- |
| 点击空格或棋盘外 | 状态不变 | 无 |
| 前方无阻挡 | 箭头飞出并从棋盘移除，剩余箭头数减 1 | 飞出动画或位移效果 |
| 前方有阻挡且仍有失误次数 | 箭头保留，失误次数减 1 | 前冲回弹、晃动、变色或提示文字 |
| 前方有阻挡且失误次数归零 | 当前关卡进入失败状态 | 碰撞反馈后显示失败界面 |
| 移除最后一支箭头 | 当前关卡进入通关状态 | 最后一次飞出反馈后显示通关界面 |

### 4.4 失误次数

- 每个关卡设置失误次数，默认值为 3。
- 点击被阻挡箭头消耗 1 次失误机会。
- 点击空格、棋盘外或无阻挡箭头不消耗失误机会。
- 失误次数应在游戏界面持续显示。
- 重新开始当前关卡时，失误次数恢复为初始值。

## 5. 页面与交互需求

### 5.1 开始界面

必须包含：

- 游戏标题“一箭又一箭”；
- 简短规则说明；
- “开始游戏”按钮；
- 四种方向箭头的可理解展示或说明。

点击“开始游戏”后进入第 1 关，并初始化棋盘和失误次数。

### 5.2 游戏界面

必须包含：

- 当前关卡名称或编号；
- 棋盘；
- 剩余箭头数量；
- 剩余失误次数；
- “重新开始”按钮。

交互要求：

- 鼠标点击箭头后执行路径检测。
- 鼠标点击空格或棋盘外不改变状态。
- 动画播放期间应暂时忽略重复点击，避免一次操作产生多次状态变化。
- 窗口调整大小后，棋盘和箭头仍应完整显示，不能明显重叠或裁剪。

### 5.3 通关界面

清空当前关卡后显示通关结果，至少提供：

- 通关提示；
- 进入下一关的操作；
- 重新开始当前关的操作；
- 返回开始界面的操作。

最后一关通关后，应显示“全部通关”结果，不应进入不存在的下一关。

### 5.4 失败界面

失误次数耗尽后显示失败结果，至少提供：

- 失败提示；
- 重新开始当前关；
- 返回开始界面。

重新开始后，棋盘应恢复到该关初始布局，失误次数恢复为 3。

## 6. 关卡需求

### 6.1 数量与质量

- 至少设计 3 个关卡。
- 每个关卡必须实际试玩验证。
- 每个关卡必须存在合理的通关顺序。
- 每个关卡的布局应不同，并具有逐步增加的观察或操作难度。
- 关卡不能出现无解布局。

### 6.2 关卡数据建议

可以使用字符网格保存关卡，例如：

```text
{
    "name": "第 1 关 · 入门",
    "layout": [
        "→··↑·",
        "··↓··",
        "↑····"
    ],
    "mistakes": 3
}
```

建议将关卡数据与界面绘制代码分离，使关卡调整和可解性测试更加方便。

## 7. 状态与数据模型

### 7.1 游戏状态

建议至少包含以下状态：

```text
START       开始界面
PLAYING     游戏中
WON         当前关通关
FAILED      当前关失败
ALL_CLEARED 全部关卡通关
```

### 7.2 箭头状态

建议将箭头的显示状态分为：

```text
IDLE      正常显示
FLYING    正在飞出
BLOCKED   正在播放碰撞反馈
```

动画结束后才能执行最终状态切换：

- `FLYING` 动画结束后移除箭头，并判断是否清空棋盘；
- `BLOCKED` 动画结束后恢复正常显示，或在失误归零时进入失败界面。

### 7.3 建议的数据结构

- `Level`：关卡名称、网格布局、初始失误次数。
- `Arrow`：行号、列号、方向、显示状态和动画信息。
- `GameState`：当前关卡、剩余箭头、剩余失误次数和当前页面状态。

## 8. 逻辑与算法要求

### 8.1 路径扫描伪代码

```text
检查箭头前方是否有阻挡(arrow):
    根据 arrow.direction 得到 (row_step, column_step)
    row, column = arrow.position + step
    while position 在棋盘范围内:
        if 该位置存在其他箭头:
            返回 blocked
        row, column = row + row_step, column + column_step
    返回 clear
```

实现时必须先判断坐标是否在边界内，再访问网格数据，避免越界或负下标导致误判。

### 8.2 点击处理伪代码

```text
on_click(position):
    如果当前不在 PLAYING 状态或动画正在播放:
        忽略点击
    如果 position 不是箭头:
        不改变状态
    如果路径检测结果为 clear:
        标记箭头为 FLYING
        播放飞出动画
        动画结束后移除箭头
        如果剩余箭头为 0:
            进入 WON 或 ALL_CLEARED
    否则:
        失误次数减 1
        标记箭头为 BLOCKED
        播放碰撞反馈
        如果失误次数为 0:
            进入 FAILED
```
